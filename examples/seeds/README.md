# Seed data for training your tools

These are hand-authored seed examples for the three tools: a ready-made starting set you bring to the Distil Labs platform. We expand them into synthetic training data and train a small student model per tool.

**No frontier API key is needed to produce or use them.** They are checked in, so you can go straight from cloning this repo to a trained model without running a teacher model yourself.

## What's here

| File | Pairs | Task |
| ---- | ----- | ---- |
| `narrator.jsonl` | 25 | one PostHog session to a 3-sentence behavioral narration |
| `extractor.jsonl` | 25 | a narration to strict-JSON bug/gap findings (6 examples have no findings, so the model learns that a clean session is a valid outcome) |
| `prioritizer.jsonl` | 22 | a batch of deduplicated findings to a ranking with a reason per item |

Each line is one training example: `{ tool, teacher, input, output }`. `teacher` is set to `"human-seed"` so you can tell these were written by hand rather than generated by a model. Every `input` and `output` already matches the shape its tool defines in [`../../src/tools/registry.ts`](../../src/tools/registry.ts), so the examples are in the exact format the trained model will read and produce.

## How to use them

1. **Send us the JSONL** as seed data. We expand each tool's seeds into a synthetic training set and return a fine-tuned model per tool. Host each model on your own runtime (Ollama, vLLM, an OpenAI-compatible endpoint).

2. **Pin your models** per tool and run on the SLM engine, no frontier key:

   ```bash
   TOOL_NARRATOR_MODEL=<your-narrator-model> \
   TOOL_EXTRACTOR_MODEL=<your-extractor-model> \
   TOOL_PRIORITIZER_MODEL=<your-prioritizer-model> \
   bun run demo
   ```

3. **Extend with your own product's data.** These seeds describe a generic SaaS app (dashboard, reports, billing, onboarding, integrations). For a model that understands *your* product, add examples from your own PostHog sessions in the same format. More seeds and more variety improve the student.

## Regenerating

The files are generated from typed, schema-validated source in [`../../scripts/build_seeds.ts`](../../scripts/build_seeds.ts):

```bash
bun run build-seeds
```

Edit the authored data there (or add rows) and rerun. The script validates every pair against the tool schemas and checks that each prioritizer batch ranks every finding exactly once, so a bad edit fails loudly instead of writing broken JSONL.
